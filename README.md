# 🩺 Playwright Test Fixer: an MCP server for your IDE

When a Playwright test fails, ask the AI in **IntelliJ** (or VS Code) *"why is TC-004 failing?"*.
Through this [MCP](https://modelcontextprotocol.io) server the AI **runs the test**, reads the error, the
failing lines, the page-object locators and a **snapshot of the page at the moment of failure**, opens
the live page to see the **real locators**, and **proposes a fix as a diff**. Nothing is written until
**you approve it**; then the change lands in your JavaScript files and the test is re-run.

Works with any MCP-capable AI plugin (GitHub Copilot, Claude Code, JetBrains AI Assistant, DevoxxGenie)
and any model; set up here with **GitHub Copilot** in a JetBrains IDE.

## What a session looks like

```
You:  TC-004 is failing, fix it.
AI:   → run_tests(grep="TC-004")          [FAIL] FR-03 › TC-004 … Test timeout of 30000ms exceeded.
      → get_failure_details("TC-004")     waiting for getByTestId('checkout-btn') · line 20
                                          cartPage.checkoutButton → object-repository/CartPage.json
                                          page snapshot: button "Checkout" is on the page
      → inspect_page("/cart.html")        getByTestId('checkout') [button, unique] Checkout
      → propose_fix(CartPage.json, "checkout-btn" → "checkout")
AI:   The Checkout button's test id is "checkout", but the object repository says "checkout-btn".
      Fix 3f9a1c2e (nothing written yet):
        -      "value": "checkout-btn",
        +      "value": "checkout",
      Apply it?
You:  yes
AI:   → apply_fix("3f9a1c2e")  → run_tests(grep="TC-004")   1 passed ✅
```

## Tools

| Tool | What it gives the AI |
|---|---|
| `run_tests(spec, grep)` | Runs `npx playwright test` with the JSON reporter; pass/fail per test with the first error line. Reports setup problems (no `npm install`, no `.env`, no browser) in plain words. |
| `get_failure_details(test)` | Error and call log, the failing spec lines (marked), the **page-object elements on those lines with their locators and JSON file**, the **accessibility snapshot of the page when it failed**, and hints for common causes (strict-mode violation, missing element, still on the login page, wrong text…). |
| `inspect_page(url_path)` | Opens the page in a headless browser (logging in with the project's own `LoginPage` and `.env`) and lists elements with working locators, and whether each is **unique** and **visible**. |
| `find_elements(query)` | Searches the object repository (`"cart button"` → `commonPage.shoppingCartLink`) so fixes reuse page objects instead of raw locators. |
| `read_file`, `list_project_files` | Project files with line numbers. `.env`, `node_modules` and `.git` are off limits. |
| `propose_fix(file, old_text, new_text, reason)` | Prepares a change and returns a **diff + fix id**. **Writes nothing.** Rejects changes that would break JSON or JavaScript syntax (`node --check`). |
| `apply_fix(fix_id)` | Writes an approved fix, after checking the file hasn't changed since the proposal; keeps a backup. |
| `undo_fix(fix_id)`, `list_fixes()` | Restore the backup; see pending / applied / undone fixes. |
| Prompt **`/fix_failing_test`** | Slash command that runs the whole guided workflow. |

### Human in the loop, enforced in three places
1. `propose_fix` can't write. Only `apply_fix` writes, and only a fix that was proposed, to a file that
   hasn't changed since (so it never overwrites your own edits). Every apply is backed up and undoable.
2. The server instructions tell the model to call `apply_fix` only after you say yes to that fix id.
3. `apply_fix` and `undo_fix` are marked *destructive*, so IDE plugins ask before running them (keep
   auto-approve off in Copilot so you confirm each tool call).

Credentials stay on your machine: the AI can't read `.env`, and `inspect_page` logs in inside a local
browser process.

## Setup (macOS) with IntelliJ / PyCharm + GitHub Copilot

**1. Install the server** (Python 3.10+):
```bash
cd ~/AI/QA_playwrightMCP
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

**2. Have a Playwright project ready** (e.g. one generated by the AI Automation Code Generator):
```bash
cd ~/AI/playwright-pom-saucedemo-com
npm install
npx playwright install chromium
cp .env.example .env      # then fill in BASE_URL, APP_USERNAME, APP_PASSWORD
```

**3. Install GitHub Copilot:** Settings → Plugins → Marketplace → **GitHub Copilot** → Install →
restart, then sign in with your GitHub account (Copilot icon in the toolbar).

**4. Add the server:** Settings → Tools → **GitHub Copilot** → **Model Context Protocol (MCP)** →
**Configure**. This opens `mcp.json`: paste [`examples/copilot/mcp.json`](examples/copilot/mcp.json)
with your two paths, and save. The server shows up with its 10 tools.

**5. Use it:** open Copilot Chat, switch the mode to **Agent**, and ask *"Run the tests and fix the
failing ones"*. Copilot asks before each tool call; approve `apply_fix` only for a diff you agree with.

### Other AI plugins
The server is a standard stdio MCP server, so the same command works in any client
(some use `mcpServers` as the top-level key instead of `servers`):

```json
{ "mcpServers": { "playwright-fixer": {
    "command": "/Users/you/AI/QA_playwrightMCP/.venv/bin/playwright-fixer",
    "env": { "PW_PROJECT_DIR": "/Users/you/AI/playwright-pom-saucedemo-com" } } } }
```
- **Claude Code** (JetBrains plugin / terminal): `claude mcp add playwright-fixer -e PW_PROJECT_DIR=$PWD -- ~/AI/QA_playwrightMCP/.venv/bin/playwright-fixer`
- **JetBrains AI Assistant** and **DevoxxGenie** (works with a Groq key): add the JSON above in their MCP settings.

Every tool also takes an optional `project_dir`, so one server can work on several projects.

## How it works

```
pwmcp/
  server.py         MCP tools, prompt and instructions (MCP Python SDK 2.x, stdio)
  runner.py         runs Playwright with the JSON reporter; parses results, stack frames and
                    error-context.md (page snapshot); builds failure details and hints
  inspector.py      runs inspect_page.js inside the project (its own @playwright/test + LoginPage)
  fixes.py          propose → apply → undo, with diffs, syntax checks, conflict check and backups
  project.py        project location, path safety (.env/node_modules blocked), object-repository search
```

Fixes, backups and the last run are kept in `<project>/.pwmcp/` (git-ignored automatically).

## Tests

```bash
pip install -e ".[dev]"
pytest
```
- `tests/test_core.py`: path safety, repository search, proposal validation, apply/undo and conflict
  rules, report parsing, hints.
- `tests/test_mcp.py`: **end to end over real MCP**. It starts the server over stdio like an IDE does,
  breaks a locator in a generated project, then runs → diagnoses → inspects → proposes → applies → re-runs
  green against a local practice shop (needs Node.js; set `PW_TEST_VERSION` to pin `@playwright/test` to
  your installed browser build).

Tested with MCP clients from SDK 1.x and 2.x (protocol 2025-11-25 and newer).

## Limitations
- The AI's diagnosis is only as good as the model; the server makes sure it has the facts (error,
  code, locators, live page) and that it can't change code without you.
- Tests that depend on data or timing outside the browser (emails, back-end jobs) can be run and
  explained, but their fixes usually need a human.
